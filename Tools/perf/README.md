# perf

Measures Helio in the iOS simulator, or as a Mac Catalyst app on this Mac, against fixture Reddit data: Reddit API requests by endpoint, link-preview downloads, main-thread CPU, frames over budget ("hitches"), memory, and how soon a post's comments are requested. No Reddit account or network is needed.

```bash
swift build --package-path Tools/perf -c release
alias perf=Tools/perf/.build/release/perf

perf build head                    # Release build of this checkout, labeled "head"
perf bench head                    # three runs of the benchmark, then the medians
perf build base --repo ../other    # another checkout, such as a worktree at main
perf bench base
perf compare base head
perf check head                    # fail if Reddit requests exceed budget.json
perf bench head --runs 1 --profile # with Time Profiler
perf stalls head                   # main-thread stalls while scrolling Home, and what ran in them
perf stalls head --from post_open --to cscroll_end
perf callers head _swift_getKeyPath

perf build mac-head --mac          # Mac Catalyst build; bench, compare, stalls and callers then run on this Mac
perf bench mac-head
perf stalls mac-head --from resize_start --to resize_end
```

Results go to `$HELIO_PERF_DIR` (default `$TMPDIR/helio-perf`)`/<label>`: `build.log`, `run<n>.log`, `summary.json` and, when profiled, `run<n>.trace`. Runs use the simulator in `$HELIO_PERF_SIMULATOR`, or a "Helio Perf" iPhone the tool creates, so other simulators aren't disturbed. For an iPhone Duo run, create a Duo simulator (`xcrun simctl create "Helio Perf Duo" com.apple.CoreSimulator.SimDeviceType.iPhone-Duo <Duo runtime>`) and pass its UDID in `HELIO_PERF_SIMULATOR`. It boots folded, the narrow display with the side tab bar; the simulator can't unfold it from the command line, so only the folded layout is measured.

## How a run works

1. `PerfSetupUITests` (in `App/HelioUITests`, skipped unless run by this tool) installs the app fresh, launches it with the shim and a placeholder account, and goes through onboarding and What's New.
2. The app is launched again with `simctl`, as a returning user, with the shim (`Shim/HelioPerfShim.swift`) loaded through `DYLD_INSERT_LIBRARIES`. The shim answers every request from the fixtures with 150 ms of latency (60 ms for non-Reddit hosts), logs requests, samples CPU, memory and frames every 250 ms, and runs the scenario's commands.
3. The scenario (`Bench.scenario`) opens Home through a deep link, scrolls it through its four pages, opens a post and scrolls its comments. It marks `home_open`, `scroll_start`, `scroll_end`, `post_open`, `cscroll_start`, `cscroll_end` and `end`, and metrics are reported for the windows between them (`feed`, `post`, `all`). Navigation and scrolling happen inside the app: XCUITest's accessibility snapshots took about a fifth of the main thread and caused hitches of their own.

The fixtures (`Sources/perf/Fixtures.swift`) are seeded, so every run sees the same 100 posts and comment threads, and request counts repeat exactly from run to run. Images are generated by the shim and videos don't load.

## On Mac

`perf build <label> --mac` makes an unsigned Release Mac Catalyst build under its own bundle id (`com.sertacozercan.helio.perf`) with its URL schemes removed, so it never shares preferences or saved state with an installed Helio and never answers helioapp:// links. Every other command works on that label as on a simulator one. Each label builds from scratch (about ten minutes): a copied derived-data folder doesn't build, as its module caches record their path.

Each run starts from an empty home folder (`CFFIXED_USER_HOME`, which holds the caches, Core Data store and saved state) and deletes the build's preferences, which don't follow `CFFIXED_USER_HOME`. An unprovisioned Catalyst build can't use the keychain, so the shim answers `SecItem` calls from memory ($PERF_MEMORY_KEYCHAIN). That keeps the user's keychain out of it too. The app launches once to sign in and load the account, then again for the measured scenario, as a returning user whose token has expired.

The Mac scenario sets a 1440×900 window and runs the iPhone one (`feed`, `post`), then two things only the Mac does: `resize` drags the window from 1440 to 820 points wide and back, twice, which lays every column out again each frame, and `switch` opens six posts one after another through links, each stacking on the post column (last, as the stacked pages stay alive). Its `all` window covers these too, so don't compare Mac and simulator labels.

Resize steps set the AppKit window's frame (as dragging its edge does) and log their count and average time as `resize_steps=`. The window comes to the front during a run. Leave the Mac alone until it finishes: other apps take CPU, and a covered window stops drawing frames.

## Reading results

- Request counts are exact. Main-thread CPU varies by about 5% between runs, and hitch time by about 10%, so compare medians of three runs and treat smaller differences as noise.
- Don't compare a profiled run with an unprofiled one: Time Profiler adds main-thread time.
- Absolute numbers depend on the Mac, the simulator runtime and the fixtures; only compare labels measured on the same machine.
- A build from before a change that fixed slow comment loading may log `nothing to scroll`: its comments weren't loaded 5 s after the post opened. Its request counts are still valid.

## Budget

`budget.json` lists the Reddit requests one benchmark run may make, in total and by endpoint. The Perf workflow runs `perf check` on pull requests that touch the app. When a change saves requests, lower the counts; when it needs more on purpose, raise them and say why in the pull request.
