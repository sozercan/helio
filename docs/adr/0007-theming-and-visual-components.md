# ADR-0007: Theming, Layout, and Visual Components

Status: Accepted

## Context

Helio renders dense Reddit feeds, nested comment threads, media lightboxes, and settings across iPhone, iPad, Mac Catalyst, and foldable iPhone Duo layouts. Its visual layer must satisfy strict accessibility contrast targets (WCAG AA by default and WCAG AAA in High Contrast), preserve native iOS 26 Liquid Glass and Mac toolbar conventions, survive dynamic window resizing and fold/unfold layout transitions without losing scroll or network state, and avoid SwiftUI/UIKit layout and memory traps (stack overflows in Debug builds, frame-caching bloat in GIFs, and hit-testing or VoiceOver quirks).

## Decisions

### 1. Theme Storage, Palette Architecture, and Accessibility Contrast

- **Copy-on-write boxing for large theme and swipe-action structs** (`Sources/HelioKit/models/HelioTheme/HelioTheme.swift`, `Sources/HelioKit/globals/Boxed.swift`): `HelioTheme` (~4 KB) stores its payload in a copy-on-write `Parts` box, and large theme/swipe-action sub-structs use `@Boxed`. Every view reading `useTheme` from the SwiftUI environment holds a copy; inline storage bloated view structs to kilobytes, and unoptimized Debug builds repeatedly copying views on the stack during deep layout passes (such as rotation) exhausted the main-thread stack. `@Boxed` encodes transparently as the wrapped value, with one `Codable` caveat: synthesized coding writes a boxed `nil` as `null` and requires the key when decoding, so optional fields may only be boxed in types with custom `Codable` conformance.
- **Thread-safe theme color cache** (`Sources/HelioKit/models/HelioTheme/sharedThemeModels/ThemeColor.swift`): `ThemeColorsCache` protects its dictionary with an `NSLock` because theme colors are resolved off the main thread during parallel post construction (`Post.initMultiple`), where unsynchronized writes would crash.
- **Palette-driven built-in themes with shared `general` settings** (`Sources/HelioKit/globals/defaultTheme.swift`): Built-in themes share identical layout and sizing (Apollo's geometry) and vary only through `ThemePalette` passed to `HelioTheme(palette:)`. Every built-in theme keeps identical `general` settings (bars and app tint) because changing `general` requires an app restart.
- **WCAG AA contrast in default themes and Increase Contrast overrides** (`Sources/HelioKit/globals/defaultTheme.swift`, `Sources/HelioKit/components/VoteButton.swift`):
  - Default tertiary grey is intentionally lighter than Apollo's so small text meets 4.5:1 on cell and flair backgrounds; quote text (`#9294A0` on black) is darkened in light mode to maintain 4.5:1 on white.
  - Secondary text outside themed cells uses a dedicated `secondaryText` color rather than opacity-dimmed primary text so it keeps 4.5:1 contrast and responds to Increase Contrast.
  - Voted score text uses darker/lighter shades than vote button fills (which are 3.1:1 on white and too dark on black) to reach 4.5:1.
  - Increase Contrast system palettes map comment depth bars to iOS Increase Contrast system colors (≥3:1 on white and black) and greys to `highContrastPalette` (7:1 for secondary/tertiary text, ≥3:1 for separators on cells and grouped list rows).
- **WCAG AAA High Contrast theme** (`Sources/HelioKit/globals/defaultTheme.swift`, `Sources/HelioKit/views/Settings/views/AppearancePanel.swift`): The High Contrast built-in theme enforces ≥7:1 text contrast and ≥3:1 divider/separator/depth-bar contrast in both light and dark modes regardless of the system Increase Contrast toggle:
  - Accent blue is tuned beyond iOS Increase Contrast blue (`#0040DD` light / `#409CFF` dark) so "load more" text reaches 7:1 on its grey pill.
  - Voted scores override Apollo's ~4.9:1 orange/indigo, and unvoted post-page scores override ~3.5:1 grey with `fontSecondary`.
  - Feed dividers switch from a thick ~1.2:1 band (which would be visually heavy at 3:1) to a 1pt hairline in the separator color.
  - Uncolored flair and NSFW pills replace translucent grey (~3.3:1) and translucent red (~3.5:1) with opaque dark fills reaching 7.9:1 text contrast while still standing out on black (2.7:1).
  - Settings Appearance panels read `secondaryText` from the applied theme's `statsText` so High Contrast descriptions also reach 7:1.
- **Single-appearance rasterized title flair** (`Sources/HelioKit/models/HelioTheme/PostLinkTheme.swift`, `Sources/HelioKit/models/RedditEntities/Post/Post.swift`, `Sources/HelioKit/components/Prepend.swift`): Uncolored title flair is rasterized once into the title attributed string/image and therefore uses a single non-adaptive color rather than light/dark variants. When `titleFlair` is `nil`, a fixed translucent grey reads as a grey pill on both white and black; decoding leaves missing `titleFlair` as `nil` (rather than falling back to a default) for backwards compatibility with older saved themes.
- **Liquid Glass and translucent sheets** (`Sources/HelioKit/views/Tabber/Tabber.swift`, `Sources/HelioKit/components/Modals/ReplyModal.swift`): Blurry themes skip `UIBarAppearance` overrides so iOS 26 Liquid Glass and scroll-edge effects remain system-managed, and skip `.presentationBackground` on sheets like `ReplyModal` to preserve the system glass sheet; only opaque theme colors override bar or sheet backgrounds.

### 2. Window Metrics, Foldable Layouts (iPhone Duo), and Platform Chrome

- **Reactive `WindowMetrics` instead of screen bounds** (`Sources/HelioKit/extensions/Numbers/NumbersScreenInfo.swift`, `Sources/HelioKit/AppDelegate.swift`, `Sources/HelioKit/views/AppContent.swift`, `Sources/HelioKit/views/Settings/views/theming/Editing/ThemingCategories/PostLink/PostLinkThemingPanel.swift`):
  - `screenW` and `screenH` read reactive `WindowMetrics` rather than `UIScreen.main.bounds` so views re-render on window resize (iPhone Duo fold/unfold, iPad multitasking, Mac window resizing).
  - `WindowMetrics.shared` is eagerly touched on the main thread at launch because its first read accesses `UIApplication`.
  - `AppContent` injects window `contentWidth` into the environment at the root for all tabs while allowing the split-view posts column to override it locally. Panels inside iPad form sheets (such as `PostLinkThemingPanel`) measure their own width because form sheets are narrower than the window.
- **Readable width and iPhone Duo hinge/safe-area invariants** (`Sources/HelioKit/globals/ReadableWidth.swift`):
  - `ReadableWidth.contentWidth` disables the 700pt readable-width cap when a column spans the open iPhone Duo hinge (a centered column would straddle the hinge), while keeping the cap for single-side panes.
  - `ColumnContentWidth` applies `.frame(maxWidth: .infinity, maxHeight: .infinity)` before `.onGeometryChange` so it measures the enclosing column rather than its child content, and intersects the column frame with `metrics.contentFrame` because folded iPhone Duo columns extend under the vertical side tab bar.
  - Open iPhone Duo split-pane `NavigationStack`s inherit phantom window safe-area insets (such as the side tab bar) along the hinge edge (`paneHingeEdges`). Every screen pushed in a pane's stack must apply `ignoresPaneHingeInsets()`; otherwise lists inset rows by the side tab bar width while laying them out for the full pane, causing rows to overflow the opposite edge.
- **Screen state handoff across layout rebuilds (`ScreenStates`)** (`Sources/HelioKit/globals/ScreenStates.swift`):
  - Folding or unfolding iPhone Duo switches the posts tab between `NavigationSplitView` and two custom panes (`SubredditsStack`), rebuilding every screen anew. `ScreenStates` preserves feed, post, and web-page models across transitions by matching `(name, owner)` via object identity (not entity ID, which can change once details load).
  - Uses a two-phase `lease(_:owner:make:)` (at `init`) and `adopt(in:)` (on appear) protocol because SwiftUI constructs and discards transient view structs and `@State` retains only the first `init`'s lease.
  - `holders` is incremented at `lease` time so screens built underneath another pushed screen (such as a post beneath a web page) retain their handed-over model past the 2-second handoff window; `adopt` checks `from == handoff` without re-checking `handoffEnds` so uncovered screens still claim their held entry.
  - Safety invariants: `Entry.owner` is weak to prevent ABA pointer-reuse collisions; `claimedIn` ensures at most one new-layout screen claims a handed-over model; concurrent-init races resolve to another unclaimed entry or a fresh model, and `ScreenStateLease.model` remains observed (not `@ObservationIgnored`) so views update on replacement; `settled` signals final model identity so single-parent UIKit views (`WKWebView`) wait before attaching; `handedOff` retains departing entries until the handoff ends; zero-holder entries are pruned before starting a new handoff so abandoned models cannot leak into later visits; handoffs are scoped to a single layout container (leaving other tabs untouched) and support `endsItself: false` so unit tests avoid main-actor timing races.
- **Tab bar, Mac toolbar, and platform-specific chrome** (`Sources/HelioKit/views/Tabber/Tabber.swift`, `Sources/HelioKit/extensions/ViewModifiers/touchScrollIndicators.swift`, `Sources/HelioKit/views/Settings/Settings.swift`, `Sources/HelioKit/extensions/ViewModifiers/closeSheetBtn.swift`):
  - On Mac Catalyst, the iOS tab bar is hidden (`hidesTabBarOnMac`) in favor of `MacTabToolbar`, and screens extend under the toolbar (like Reminders) so theme backgrounds and the subs sidebar fill full window height while UIKit safe area keeps content below the toolbar.
  - On iOS 26, Search uses `role: .search` so it renders as a separate trailing glass button. Wide layouts (iPad, unfolded iPhone Duo) use `.tabBarMinimizeBehavior(.automatic)` because `.onScrollDown` prevents the posts split view from showing its sidebar.
  - Mac Catalyst forces `.automatic` scroll indicators so macOS's "Show scroll bars" preference is respected for pointer users, and forces `.navigationBarTitleDisplayMode(.inline)` in Settings to match native Mac settings windows.
  - iPad form-sheet close buttons use a 44pt hit target extending below the top edge because taps on a bare 24pt icon near the top edge fail hit-testing.

### 3. Post Rows, Canvas Grid, Media Layout, and Post Page State

- **Title measurement and font-scaling parity** (`Sources/HelioKit/components/Prepend.swift`, `Sources/HelioKit/components/Links/PostLink/getPostContentWidth.swift`, `Sources/HelioKit/views/PostView/PostContent.swift`): `createTitleTagsAttrString` and `getPostDimensions` must scale title and tag fonts identically with `dynamicTypeSize` / `ContentTextScale` so rendered titles match pre-measured row heights. `PostContent` explicitly reads `contentTypeSize` because Markdown sets its own font sizes.
- **Media sizing, column-width preservation, and split-view isolation** (`Sources/HelioKit/components/Links/PostLink/getPostContentWidth.swift`, `Sources/HelioKit/models/RedditEntities/Post/Post.swift`, `Sources/HelioKit/models/RedditEntities/Post/PostHelioData.swift`, `Sources/HelioKit/views/PostView/PostContent.swift`, `Sources/HelioKit/views/PostView/PostView.swift`):
  - When Reddit omits media dimensions, `getPostDimensions` defaults to a square (matching media views to avoid layout jumps) and never reuses the window-height-capped cached layout size as source aspect ratio.
  - `Post.setupHelioData` preserves `lastWidth` when `contentWidth` is `nil` (refresh, theme change) so split-view posts do not snap to full window width. Async Streamable resolution re-reads `helioData?.layoutWidth` rather than a captured width to prevent stale-width relayouts.
  - `PostHelioData.pageLayout` is stored separately from feed row dimensions because in split view the feed row and post page occupy columns of different widths. `PostView` must not apply `.relayoutPosts` (which would fight the side-by-side feed row), and `PostContent` subtracts the feed's full-bleed horizontal inset so post-page media remains inset.
- **Media sharing, compact copies, deferred metadata, and avatars** (`Sources/HelioKit/models/RedditEntities/Post/Post.swift`, `Sources/HelioKit/models/RedditEntities/Post/PostHelioData.swift`):
  - Non-compact rows share `extractedMedia` with `extractedMediaForcedNormal` to avoid building duplicate players, embedded posts, and link previews. Compact rows keep a separate copy so switching to Large works cleanly, requiring both copies to be updated for deferred media and inspected by `avatarSubjects`.
  - `fetchItself()` defers layout until a linked post is opened (`layoutIfNeeded`) to prevent recursive link-extraction cascades across linked posts.
  - Canvas feeds defer link-preview downloads, Streamable video resolution, and linked Reddit entity fetches (`deferredMedia`) until media actually displays (e.g., on post open). Once displayed, `deferredMediaShown` flips the post to eager loading so subsequent refreshes load visible media immediately.
  - On relayout, cached avatars are rebound onto rebuilt embedded crosspost `Post` objects without triggering premature lookups on fresh pages; a page's posts and crossposts are registered together in one `updatePostsWithAvatar` call so they stay inside `AvatarLoader`'s coalescing window.
  - Local read state (`helioSeen`) is copied from existing `PostData` on refresh because Reddit does not store it.
- **Canvas grid rules** (`Sources/HelioKit/globals/PostLayout.swift`, `Sources/HelioKit/components/Links/PostLink/PostCanvas.swift`):
  - Saved excludes canvas layout because Saved includes comments that canvas tiles cannot render. Switching to canvas preserves the subreddit's underlying compact setting for when canvas is later disabled.
  - Across a foldable hinge, canvas forces an even column count (half on each side) so no tile is split by the hinge.
  - Canvas thumbnails validate `http`/`https` scheme and host to reject Reddit's non-URL sentinel strings (`"self"`, `"default"`, `"nsfw"`, `"spoiler"`), select renditions by shorter side (since tiles center-crop to a square), and check NSFW/spoiler flags on both the crosspost and its original post when blurring.
  - `CanvasTile`'s `Equatable` compares `post` and `sub` by reference identity (`===`) so refreshes delivering new model instances for the same IDs still re-render updated scores and votes.
- **Selection highlights, read-on-scroll, and tap isolation** (`Sources/HelioKit/components/ThemedForegroundBG.swift`, `Sources/HelioKit/components/Links/PostLink/PostLink.swift`, `Sources/HelioKit/components/Badge.swift`, `Sources/HelioKit/views/PostView/PostContent.swift`):
  - Active-row highlighting in `ThemedForegroundBG` is gated on `!isWideLayout || isInSidebar` because the subs sidebar uses native list selection.
  - `OpenPostHighlight` sits outside the read-post opacity fade (opening a post marks it read) and excludes embedded crosspost secondary cards (which carry the original post's ID). List rows pair a 0.12 accent tint (~1.2:1 contrast on white) with a 3pt solid accent leading bar for legibility; canvas tiles use a stroked outline because a translucent tint barely shows over images.
  - Read-on-scroll marks posts read only after scrolling fully past the top rather than in `onDisappear`, which falsely fires on upward scroll, tab switches, or opening a post.
  - `Badge` gives the stats line its own tap target so SwiftUI does not route taps on it to the nearest tappable view (the author name) instead of the row.
  - Collapse-on-tap in `PostContent` attaches only to title and text, never to media, because clicks on Mac web-view video controls bubbled up and collapsed the post.
- **PostView lifecycle, comment loading, and scroll restoration** (`Sources/HelioKit/views/PostView/PostView.swift`):
  - `PostView.==` excludes comments and sort because the observed `PostSession` drives those updates directly.
  - All comment/post loads go through one latest-request-wins entry point; comment sort actions are disabled during initial load (`!hideElements`) to prevent duplicate fetches; `seenComments` is snapshotted before fetch because loading overwrites stored seen comments; top-level replies set `ignoreSpecificComment = true` so the reload shows the full thread rather than remaining scoped to a deep-linked comment.
  - Assigning loaded comments is unanimated so the list does not build and measure every new row in one long frame.
  - `PostSession` reference-counts `shownRowIDs` (instead of using a `Set`) because old and new lists overlap during layout transitions, tracks user-initiated scrolling separately from programmatic scrolls so returning to the post's top takes precedence over `highlightID` on handoff, and records raw visible row IDs on scroll stop while deferring `CommentTree.rows` flattening until a layout handoff actually needs the topmost row.
  - `PostView` uses `.safeAreaBar(edge: .bottom)` so the list reserves space for the bottom bar, hides the non-interactive floating pill and skips menu-bar command registration when `isPreview` is true (context-menu previews), keys command target updates by `ObjectIdentifier(post)` so refreshed `Post` instances stay bound, and uses 3-tier `ViewThatFits` degradation (full pill → drop ratio → compact menu) to prevent score-ratio wrapping in narrow windows or large text.

### 4. Interactive Components, Accessibility Proxies, and Web/Modal Quirks

- **Scrubbable GIF playback** (`Sources/HelioKit/components/ScrubbableGIF.swift`): `ScrubbableGIFView` replaces Gifu where scrubbing is needed. It decodes one frame at a time off the main thread (non-isolated `async` `decodeFrame`) with `kCGImageSourceShouldCacheImmediately: true` and `kCGImageSourceShouldCache: false` so memory stays at roughly one frame regardless of GIF length. It applies the browser-standard 0.1s fallback for zero/near-zero frame delays, throttles `onPlayhead` via `reportedFrame` to once per GIF frame (not per screen refresh), returns `pixelSize` from `intrinsicContentSize` so `.scaledToFit()` preserves aspect ratio, runs `CADisplayLink` only while attached to a window to avoid retain cycles, and keeps `GIFScrubber.view` `@ObservationIgnored` with `position` read only by the progress bar so playback does not redraw the lightbox.
- **Gestures and Reduce Motion** (`Sources/HelioKit/extensions/ViewModifiers/PinchToZoom.swift`, `Sources/HelioKit/globals/consts.swift`): `PinchToZoom` adjusts `startLocation` when `gesture.numberOfTouches` changes mid-gesture to prevent the zoomed image from jumping. Spring animations that finish gestures (such as swipe snap-back) fall back to a short non-overshooting ease-out when Reduce Motion is enabled.
- **VoiceOver proxies** (`Sources/HelioKit/components/AlphabetJumper.swift`, `Sources/HelioKit/components/Links/PostLink/PostLinkTitle.swift`):
  - `AlphabetJumper` collapses the section index into a single VoiceOver adjustable element (matching UIKit's table index) and clamps both increment and decrement against `0` and `letters.count - 1` because the backing list may shrink.
  - `PostLinkTitle` places a `Color.clear` background button proxy behind the hidden UIKit title label (which VoiceOver cannot read) to expose the title and post actions (`secondary` embedded crosspost cards never read as the open post). Using a clear background rather than the label frame prevents VoiceOver from outlining blank trailing lines laid out by the label.
- **Modals, sheets, sharing, and swipe actions** (`Sources/HelioKit/components/Links/PostLink/PostLink.swift`, `Sources/HelioKit/components/ShareSheet.swift`, `Sources/HelioKit/views/AppContent.swift`, `Sources/HelioKit/components/LogOutConfirmation.swift`, `Sources/HelioKit/components/Modals/ReplyModal.swift`, `Sources/HelioKit/globals/swiftEnvValues.swift`, `Sources/HelioKit/models/SwipeAction.swift`, `Sources/HelioKit/views/Settings/views/GeneralPanel.swift`):
  - Because `ShareLink` inside SwiftUI `.contextMenu` dismisses the menu without presenting the share sheet, `PostLink` presents `UIActivityViewController` imperatively via `ShareUtils.shareItem`, which walks to the top-most presented view controller so presentation succeeds over sheets, context menus, or fullscreen covers.
  - `lightBoxPresenting()` is applied inside `GlobalDestinationsProvider` so presented sheets can open their own lightbox.
  - `LogOutConfirmation` is centralized on the root view so navigation bar, Mac toolbar, and menu bar triggers share one alert.
  - `ReplyModal` preserves drafts on close and deletes them only on explicit discard, and registers a `.modal` command target so menu-bar Post commands cannot navigate away and dismiss an active reply.
  - `enableSwipeAnywhere` is hoisted into SwiftUI Environment at the root instead of subscribing per swipeable row. `ToggleReadMessageAction` is excluded from `allSwipeActions` because it is a fixed, non-user-configurable swipe action for `MessageLink`.
  - `GeneralPanel` uses a single `.fileImporter` modifier switched on `importKind` because sibling `.fileImporter` modifiers shadow each other.
- **Inbox messages, deep links, and web dialogs** (`Sources/HelioKit/components/Links/MessageLink.swift`, `Sources/HelioKit/models/RedditEntities/Message.swift`, `Sources/HelioKit/models/RedditEntities/Post/PostData.swift`, `Sources/HelioKit/utils/redditURLParser.swift`, `Sources/HelioKit/extensions/ViewModifiers/listeners/openFromWebListener.swift`, `Sources/HelioKit/views/JavaScriptDialogs.swift`):
  - Private messages have no thread screen in Helio, so `MessageLink` renders unlimited body lines when a message has no destination and exposes mark read/unread in its context menu (otherwise only reachable by swipe).
  - `Message` highlights only `t1_` comment fullnames (never `t4_` message names), preferring `parent_id` over own name, and anchors permalink route matching at path start (`/r/<sub>/comments/<id>`, `/user/<name>/…`, `/comments/<id>`) so subreddits, titles, or IDs named `"r"` or `"comments"` are not misparsed. `redditURLParser` routes `/r/<sub>/comments` without a post ID to `.other`.
  - `PostData.can_mod_post` identifies moderators who may still reply on locked posts.
  - Deep links tapped from the posts tab push onto the existing stack so Back returns; links from other tabs reset to the posts tab's feed.
  - Custom `WKUIDelegate` JavaScript dialog handlers are required because WebKit otherwise silently cancels `confirm()` and returns `nil` for `prompt()`. Dialogs are titled with the requesting frame's origin rather than the top-level page to prevent cross-origin spoofing.

### 5. App Lifecycle, Audio Session, Startup, and Storage Safety

- **Bundle ownership and startup sequencing** (`Sources/HelioKit/HelioScene.swift`, `Sources/HelioKit/views/Tabber/Tabber.swift`): `@main` `App` lives in the app target (which owns bundle resources and installs `AppDelegate`). `MacUpdater` starts in `.task` rather than at launch so Sparkle's second-launch prompt does not open behind the main window. Startup credential selection, onboarding checks, and initial profile fetch run at `.userInitiated` priority so launch is not delayed by background scheduling. `WebExtensionRuntime` pre-starts at launch on Mac (and on iOS when any extension is enabled) so it is ready before the first link tap.
- **Serialized off-main audio session updates** (`Sources/HelioKit/AppDelegate.swift`): `setAudioToMixWithOthers` runs on a dedicated serial background queue because `AVAudioSession` calls can block during playback and must execute in FIFO order so the last request wins.
- **Cache scoping and atomic history import** (`Sources/HelioKit/views/Settings/views/GeneralPanel.swift`, `Sources/HelioKit/utils/importApolloReadHistory.swift`):
  - Cache sizing runs in a detached utility task to avoid hanging the main thread on large caches.
  - Unsandboxed Mac Catalyst builds share `Caches` and `tmp` with other apps, so cache sizing and clearing are strictly scoped to app-named folders (preventing hangs and deleting other apps' caches) and skip active SQLite files (`.db`, `-wal`, `-shm`, `-journal`) and Nuke cache so deleting open database files cannot crash the app.
  - `importApolloReadHistory` copies the user-selected `.zip` into a temp directory before unzipping (because `Zip` needs file access after the security-scoped URL ends) and writes into an isolated background Core Data context so a failed import leaves no partial inserts in the shared context.

## Consequences

- **Positive**: Debug builds no longer overflow the main-thread stack on complex theme/layout trees; High Contrast meets WCAG AAA without degrading default themes; fold/unfold transitions on iPhone Duo and resizing on Mac/iPad preserve scroll position, comments, and web history; media and GIF memory stay bounded; and Mac/iPad chrome behaves natively.
- **Trade-offs**: Adding new theme properties requires maintaining CoW boxing, custom `Codable` handling for optionals, and contrast tests; screens inside open iPhone Duo panes must remember to apply `ignoresPaneHingeInsets()`; and `Post` layout maintains separate feed, compact, and post-page state that must stay synchronized on refresh and relayout.
